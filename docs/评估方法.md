# 评估方法与边界

## 四种证据分别回答四个问题

| 证据 | 回答的问题 | 不能代表什么 |
|---|---|---|
| 程序规则与回归测试 | 数据一致、版本保护、预算和恢复是否正确 | 小说是否精彩 |
| 模型编辑与场景评测 | 给定事实下发现了哪些冲突 | 独立人工判断、全网查重 |
| 用户匿名阅读选择 | 这位读者更愿意读哪个片段及原因 | 所有读者偏好、统计总体优势 |
| 实际调用与工程记录 | 延迟、token、费用、失败与重试 | 供应商官方结算账单 |

## 输入冻结与修复记录

evaluations/frozen-cases.json 保存 12 个场景、每个场景两项约束、目标篇幅、四种配置和两次重复。生成时刻和哈希一起入库。冻结发生在基础工程实现后、文学质量调优前，不声称是开发前的正式预注册。

实际接入暴露了模型 JSON 字段名称、引文非逐字、工具结构输出条数等问题。我们修复接口与校验，在同一规则下补跑失败试次。全部失败保留，不只选最好结果。试次与模型调用不是同一概念：一个试次可能包含作者、编辑、修订和格式重试等多次调用。

开发和实测并行进行，整卷也经历了工程修复与恢复。第8章起增加思考型编辑和校准提示，第9章起前置篇幅检查；完整过程见 protocol-changes.json。三组开发校准案例中两种模式均为3/3，不证明模式优势。这是探索性的产品验收与机制验证，不能按严格隔离、固定软件版本的随机对照试验解释。原始源码快照、锁文件、实验输入和失败记录帮助后续复跑。

## 完整样书与旧策略对照

两部作品共用 DeepSeek 官方模型、初始玄幻设定、12 章蓝图及每章约 2,500 字的要求。完整系统采用时序状态、关键词与语义检索、两类独立编辑及最多三轮自动修订；基线保留全部核心记忆、上一章正文、单次审核和不自动返工策略。

基线是在新模型适配、持久化和提案服务上的旧策略适配，不是执行快照里的旧代码逐字复刻。两者共用基础设施，避免把旧接口无法运行误当作文学能力差。

本次测试操作者是Codex AI助手，并非自然人作者。完整卷包含外部AI通过界面的编辑干预，质量差异不能纯归因于DeepSeek工作流；API费用也不含Codex订阅或人力成本。完整系统第一章由实施者通过界面审阅、修改主角状态、拒绝依据不足的事实，并进行一次少量词语的选段改写。第5章在三轮修订后仍有“明日/后日”的期限冲突，实施者通过编辑器统一了两处时间表述，再重新审核。复审仍给出与原文一致的“改为明日”建议，实施者核对为误报后填写原因确认；模型低分与未通过状态保留。第6章还人工明确了让价三成后的七成现付、从赎牌与料钱挪用资金，以及服丹与吸尘咳嗽的先后，再重新审核；第7章还将考核明确为同日下午补审，补实手记来源、消除红灰重复分割，并写出日落收牌和前铺查封的后果。这些不是模型全自动创作成绩。第8至10章继续通过界面校正了人物触觉、收牌后果、借铃手续、知情来源与时间衔接，详细清单在 protocol-changes.json。无论批量确认还是界面确认，操作者均为Codex AI，不能冒充真实作者评价。基线按预设策略保留未通过审核的输出并记录原因。

两组平均编辑分来自不同审阅角色配置，不能直接当作独立对照质量分；整卷定点审阅使用同一规则。记录定稿字符数、模型编辑分、用量、每万字符费用、调用时长、返工与恢复事件。正文长度包含标点和换行，报告中明确使用“字符”，不冒充平台稿费字数。

## 四配置机制探针

12 场景 × 4 配置 × 2 重复，目标 96 个有效试次：

- baseline：简短核心背景，不注入冻结历史状态，不返工。
- full：注入历史状态，独立检查后可进行一次有依据的修订。
- no_memory：不注入历史状态，但检查发现违例时提供依据并修订。
- no_revision：注入历史状态，保留首稿。

这是上下文证据与返工的机制探针，不是产品检索模块的端到端消融。场景直接注入或移除手工冻结的历史状态，而非在实际向量数据库上运行完整章节图。no_memory 的修订阶段会得到编辑查证的事实，这正体现编辑补救机制，需与首稿结果分别理解。

两项约束逐项标为 preserved、violation 或 not_tested。没有触及某约束不算正确。违例必须给出续写中的连续原句，字面校验不通过会重试或记失败。报告同时保留首稿判断、最终判断、正文、修订次数与失败原因。生成和评审使用同一模型，可能存在相关偏差。

每种配置只有 24 个有效试次，而且来自同 12 个场景的重复，样本并不独立。不能仅凭一次比例差就声称普遍优势。应同时报告约束覆盖、违例数、可读性、推进分和成本。

## 真实执行图续写验收

新增 integration 入口，复用相同12个任务、四配置和两次重复，真实经过服务的上下文组装、FTS5/BGE/Qdrant、结构化状态、LangGraph写章、编辑、记忆提案、测试操作者确认和正文版本提交。grader不接收配置名称，违例引文与两项约束名称均严格校验。

为隔离历史渠道，环境由11个事先确认的档案片段与第12个续写任务组成：第1段存冻结事实，第2至11段是同一刻的中性静物片段，不推进时间；近十章摘要和核心动态文档故意没有这条远处事实。四种配置共享基础能力规则、境界条件与人物基本动机，完整配置可从真实历史文本和带来源的状态读回事实。输入及软件关键路径哈希在 evaluations/integration-protocol.json 中冻结。

这是人为制造摘要信息缺口的压力验收，不是旧流程自然遗忘率，也不评前十一章文学质量；种子文本不计入真实生成字数。它检验生产路径的恢复能力，不能把 oracle式已确认档案等同模型自动提取准确率。没有外部AI正文编辑，测试操作者按统一策略保留最终输出，即使审核未通过也写明原因确认。

原96次直接证据注入探针与这96次执行图试次分开报告，不能相加为192个独立场景。重用过的12个场景不是全新的holdout；模型自评偏差、两次重复的相关性和范围限制仍然存在。失败按尝试追加保存，图或评测恢复尽量复用原正文，不能选择最好结果。服务默认同时运行两个创作任务；八个客户端试验会排队，运行耗时包含该工程配置影响。额外正文轮次包含篇幅调整，不都是一致性纠错。

## 传输故障后的补跑

真实执行图首轮得到87个有效试次和9次ConnectTimeout；原结果与原控制器源码保存在 integration-first-pass.json 与 frozen-source-v1。确认macOS系统代理也接管localhost后，仅让本地工作台HTTP直连，官方模型请求保持原传输配置。五份生成、审阅、检索与事务核心源码哈希保持原冻结值；控制器与配置路径安全修复另记于 transport-recovery.json 和交付指纹。

只补失败项，不按分数选择。首轮的3个已定稿候选直接补评，4个已完成草稿通过产品重审再确认，正文哈希必须不变；2个没有完整稿的试次重新启动写章。原失败、旧稿与成本全部保留。之后控制端请求失败保留后台任务，主动终止验收时请求暂停。修订计数含故障前已经发生的正文轮次，费用包含旧失败。

## 匿名片段

固定从两卷第 1、3、5、7、9、12 章开头选取 500 字符；两稿取相同长度，位置不依赖模型得分。顺序用固定随机种子排列，首次投票时不显示系统身份。

用户只回答“更愿意继续读 A / B / 接近”及原因。六组全部提交后可揭晓身份。尚未投票必须写“未取得真实用户评价”，不能填零分或虚构偏好。实施者自己读过的判断另列，不能代投。

## 本轮AI子代理评阅

用户选择由子代理完成片段比较，真人评价不再作为本轮交付前提。三位Codex子代理各在不继承父会话的独立上下文中评阅六组既定片段，沿用父代理模型配置，没有取得独立响应模型标识。分别随机排列A/B与片段顺序，评审者只读取指定片段包，不提供版本身份、开发结果和他人选择。这是提示约束与上下文隔离，不是操作系统级访问沙箱。

每组选择A、B或接近，记录原因、置信度与双方原文依据。程序逐字检查36条引文、六组覆盖和片段包哈希，先封存三个原始结果的哈希，再读取版本映射并统计。原始结果不因偏好方向或结果不利而重跑；三位同类AI可能有相关偏差，18个选择仍嵌套在六组片段内，不是18个独立案例或三位自然人读者，不能判断整卷收束与长期一致性。

记录位于 artifacts/evaluation/agent-reading/agent-reading-20261018-v1；导入命令为 `.venv/bin/python scripts/import_agent_reading.py "$PWD/artifacts/evaluation/agent-reading/agent-reading-20261018-v1"`，不调用模型，可重复校验和导入，真人投票字段保持不变。汇总见[AI代理片段评审](../artifacts/evaluation/AI代理片段评审.md)。Codex子代理用量不计入DeepSeek API费用账本。

真人入口保留为可选；已阅读解盲报告的人再评相同片段不作为严格盲评。若需新的自然人盲评，应另设未看过结果的读者或新片段，并单独记录。

## 复跑与原始记录

先启动服务，再运行 novel-agent eval。mode report 不调用模型；sample、baseline、ablations、integration、audit 会产生真实费用，受同一个本地预算约束。成功试次不会重复覆盖；失败补跑追加新记录，适合查看工程恢复。严格复现实验需要从不带data、.venv、.local的独立源码目录重新安装，保留冻结输入与锁文件并重新配置密钥；单纯复制现有数据库仍会跳过已有成功试次。

data/studio.sqlite 保留全部运行、事件、用量、审计与实验。artifacts/evaluation/raw 保存直接机制探针JSON，integration保存真实执行图试次，frozen-source-v1保存后者原始冻结源码；results.json 保存综合结果；实测报告.md 为可读报告。服务中断的在途请求可能按保守上界计入估算，最终以官方账单为准。
