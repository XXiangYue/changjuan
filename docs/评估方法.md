# 测试与评估

长卷区分工程行为、检索效果、模型审阅和读者偏好。测试通过可以证明特定规则被执行，不能直接证明小说更精彩。源码分发包含测试和固定评估输入；历史数据库、完整稿件及原始实验产物不随仓库发布。

## 日常工程检查

先按 [项目首页](../README.md#start) 安装开发依赖。在项目目录运行：

```bash
.venv/bin/pytest -q
.venv/bin/ruff check src/novel_agent/studio src/novel_agent/cli.py tests/test_studio.py --select F
pnpm --dir web build
```

已安装 zsh 时，也可以使用 `./scripts/check.sh` 一次运行，并将测试 XML 写入本地 `artifacts/testing/`。测试使用夹具，不需要真实模型密钥。临时数据在项目 `.cache/` 内创建。

| 要检查的行为 | 测试入口 |
| --- | --- |
| 草稿、定稿、版本冲突与作者确认 | [test_studio.py](../tests/test_studio.py) |
| 资源、知情与伏笔事件回放 | [test_story_state.py](../tests/test_story_state.py)、[集成用例](../tests/test_story_state_integration.py) |
| 历史版本与时序检索 | [test_retrieval.py](../tests/test_retrieval.py) |
| 上下文预算与篇幅规则 | [test_context_budget.py](../tests/test_context_budget.py)、[test_length_control.py](../tests/test_length_control.py) |
| 中断恢复与费用预留 | [test_process_recovery.py](../tests/test_process_recovery.py)、[test_budget_process.py](../tests/test_budget_process.py) |
| MCP 发现、调用与权限边界 | [test_story_mcp.py](../tests/test_story_mcp.py) |

## 真实模型实验

这些命令是开发评估工具，会在本地创建或更新实验作品。请在独立克隆中准备模型配置、确认预算并启动工作台；不要拿唯一一份私人创作数据库直接进行实验。

```bash
# 第一个终端：启动本地服务
.venv/bin/novel-agent serve

# 第二个终端：选择需要的评估模式
.venv/bin/novel-agent eval --mode ablations
.venv/bin/novel-agent eval --mode integration --parallel 8
```

| 模式 | 行为与前提 |
| --- | --- |
| `ablations` | 使用固定场景比较配置；调用模型并产生费用 |
| `integration` | 运行真实工作流的固定历史输入验收；调用模型并产生费用 |
| `sample` / `baseline` | 生成完整样书或旧策略对照；依赖样书蓝图与实验配置，参见下面的限制 |
| `audit` | 对已有样书执行模型审核；需要已有作品并产生费用 |
| `report` | 汇总当前数据库中的实验结果，不调用模型 |
| `suite` | 依次运行样书、对照与场景实验，需满足各模式前提 |

报告可通过以下命令生成，输出在本地 `artifacts/evaluation/`：

```bash
.venv/bin/novel-agent eval --mode report
```

成功试次可能从已有记录继续，失败补跑会留下新的记录。若要比较不同实现，应使用各自独立的数据目录，记录源码版本、锁文件、输入哈希、模型响应标识、时间、失败和重试；不要把复用旧数据库后的跳过当作重新完成实验。

### 历史实验工具的限制

部分评估入口仍依赖开发时的本地档案：整卷对照依赖已确认蓝图；完整检索基准加载 `artifacts/resume/baseline-v1/retrieval.py` 中的旧实现快照。该快照与原始运行档案未随源码分发，**全新克隆不能直接重跑完整历史检索对照**。日常检索回归应使用上面的 `test_retrieval.py` 与 `test_reranker.py`。

已有相应档案的工作区可以运行：

```bash
.venv/bin/novel-agent eval --mode retrieval \
  --dataset retrieval-novel-v1.1 --split heldout --rerank
```

该入口不调用聊天 API，但需要本地嵌入模型；`--rerank` 不会自动下载重排模型。输出包含召回、排名、时序或版本泄漏、无答案误检和延迟等指标。数据构建、上下文重放与实写评分工具见 [脚本索引](../scripts/README.md)。

## 怎样解释结果

| 证据 | 能回答的问题 | 不能替代的判断 |
| --- | --- | --- |
| 程序规则与回归测试 | 数据、版本、预算和恢复是否满足测试条件 | 小说是否精彩 |
| 检索指标 | 给定输入是否找到正确的历史依据 | 模型是否正确理解并使用依据 |
| 模型编辑分与引用 | 模型报告了哪些问题 | 独立人工审阅、全网查重 |
| 匿名阅读选择 | 特定读者更愿意继续阅读哪个片段 | 所有读者的偏好与整体质量优势 |
| 调用与费用记录 | 本地记录的 token、延迟、重试和费用估算 | 供应商的正式结算账单 |

真实样书验收曾包含实施者通过界面修改正文、纠正记忆和解释误报的操作，因此不能宣传为模型全自动创作成绩。AI 片段评阅与真人评价需分别记录；没有真人提交时不能补造偏好。失败、未通过审核和不支持预期结论的结果都应保留。

已有短卷和固定场景的结果不能证明对所有题材、所有作者或百万字长篇有效。具体设计的来由可阅读 [实际问题与修复](实写中发现的问题与修复.md)。
