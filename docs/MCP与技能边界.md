# MCP 与创作技能：实现和证据边界

核对日期：2026-10-21。目标是让外部写作客户端复用本地作品资料与待审提案，并让规划器读取可版本化的创作规范。协议互通、技能读取、规则遵守和小说质量是四件分别验收的事。

| 层次 | 本项目的作用 | 不代表什么 |
|---|---|---|
| Function Calling / Tool Calling | 模型通过结构化参数请求函数；应用负责校验、执行及返回结果。内部规划器的 `search_story` 是绑定作品的 LangChain 工具闭包 | 函数能被模型调用，不代表经过 MCP，也不自动获得权限隔离 |
| MCP | 官方 Python SDK `mcp==2.3.0` 提供 stdio 工具发现和调用；固定作品、时间上界的适配器转发到本地工作台 HTTP 服务 | SDK 依赖集成不是自研协议栈；协议版本不等于 SDK 版本，也不证明模型选对工具 |
| Skill | `xuanhuan/SKILL.md` 保存能力边界、成长代价、伏笔和知情规则；DeepAgents 先发现描述，再通过文件工具读取正文 | 注册 Skill 不等于读取；读取不等于规则全部遵守；一份技能不构成多技能路由实验 |

Skill 的按需读取符合 [Anthropic 的渐进披露说明](https://www.anthropic.com/research/equipping-agents-for-the-real-world-with-agent-skills)和 [DeepAgents 的技能机制](https://docs.langchain.com/oss/python/deepagents/skills)。本项目对玄幻任务另加了明确的 `read_file` 指令，因此当前证据应表述为“任务指导下读取单一技能”，不声称验证了自主选择多个技能的能力。

MCP 服务只提供 `search_story`、`get_story_state`、`propose_state_changes`。启动时固定绝对根目录、作品、`before_position` 与本机端口；模型不能改目标作品、时间、地址或文件路径。查询在源端过滤；返回量超限会标明省略完整证据块或明确失败。HTTP 客户端禁用环境代理和重定向，并设置超时。提案经过作品归属、章节位置、草稿与项目版本、操作 schema、逐段原文引用及状态回放预检；回放不成立可留下明确标记的无效待审提案，但不改正式正文、记忆或状态。作者在工作台重新审阅并明确选择后才可能定稿。服务没有正式提交、任意文件和终端工具。

这是应用权限边界，不声称模型对提示注入免疫。MCP 的[工具规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)定义发现和调用消息；本项目用官方 [low-level Server](https://py.sdk.modelcontextprotocol.io/advanced/low-level-server/)精确控制 schema 和错误结果，权限校验仍由适配器与业务服务承担。内部规划器的直接检索工具与面向外部客户端的 MCP 是两条调用路径，不把前者的轨迹算作后者调用。

离线契约证据见 [MCP 汇总](../artifacts/resume/mcp-contract/summary.json)：8 项测试通过，其中 7 个真实 stdio 客户端夹具场景共 61 次工具调用，实际协商协议为 `2026-07-28` 和 `2025-11-25`。覆盖跨作品、未来、旧版本、伪造来源、错引文、回放失败、输出限额等边界。它证明协议与权限契约，不能转写为 61 次真实模型任务或工具选择准确率。

另一次[冻结的真实模型任务](../artifacts/resume/mcp-live/2026-10-21-task-v1/result.json)用 `deepseek-flash` 完成 3 次模型调用、4 次工具调用：读取工具后，按事先要求故意提交错引文、观察拒绝，再生成可回放的 5 项待审变化；正式状态前后相同。它验证这一固定短章任务中的工具使用和错误反馈，不是总体工具准确率。该书没有正式历史，查询为空，因而不证明非空历史检索效果；草稿和审核壳是人工预置夹具，也不算真实创作或文学审核成绩。

技能审计见 [原始轨迹、输出与哈希](../artifacts/resume/skill-audit.json)。新 UI 蓝图 `e0202fc0d3df4f79b6a414d516686b86` 使用 DeepAgents `0.7.28`，两次尝试均有完整 15 行技能回执（21427→21428、21445→21446），与技能 SHA-256 一致。首次尝试在读取、列目录及三次空历史搜索后发生 `GraphRecursionError`，第二次成功返回蓝图，之后有一次作者确认提交。该书当时尚无定稿正文，空搜索不证明历史检索有效，也不直接证明检索失效。账本记录 7 次模型调用、输入 39,605 token、输出 5,685 token、估算费用 0.12469 元；费用是本地账本估算，不是账单对账。

新蓝图把既有工具的解决条件、资源代价、伏笔回收及人物知情限制写进了场景和约束；但冻结 brief 和 schema 本身已要求其中大部分内容，不能归因于 Skill。原输出仍把“读懂许岱签名、未知用途”写成“不知领取人是谁”，并出现药钱已付却称欠款、私有药却称公中药等偏差。操作者在首章正文生成前修正，并保存 [作者准备记录](../artifacts/resume/live-story-v1/author-preparation.json)，两组使用同一修正蓝图。这些是 Codex 操作者的编辑干预，不是真实读者评价，也不是系统自主纠错成绩。

历史证明文件的 `awaiting_approval` 已过期：对应 `c2d94…` 实际已取消、未提交，虽可核实完整技能读取及局部输出对应；另一规划只有 harness 注册事件，更早样书缺少足够逐工具日志，不能倒推技能读取。当前回调还缺 `tool_call_id` 和明确截断标记，外层 `model.input` 也不是最终完整系统上下文。完整匹配当前短技能可证明这次读到了全文，不能推广为所有长技能都完整读取。规划器关闭了 DeepAgents 通用子代理；独立编辑角色由 Engine 工作流调度，不声称本轮验证了自主多 Agent 分工。

可用于简历的范围是：受限故事 MCP 的协议与业务权限实现、真实 stdio 契约测试、技能版本及实际读取轨迹、原始失败与作者修正。尚无 Skill 开关对照、多技能路由成功率或因果质量提升证据，不为这些项目填写提升百分比。
