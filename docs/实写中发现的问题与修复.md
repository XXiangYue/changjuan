# 从真实创作反推系统设计

本次实施者与界面测试操作者是Codex AI助手，不是自然人作者；下文“作者操作”指通过作者界面提交的动作，不是用户阅读评价。这份记录说明本轮实写怎样影响实现。案例发生在《余烬照山河》和独立验收作品中，不代表所有小说都会出现相同问题。

| 暴露的问题 | 修复与作者入口 | 验证 |
|---|---|---|
| 模型引用会抄错一个字、改写原句 | 审核与事实提取引用段落编号，由程序取原文 | 字面引用回归；真实章节恢复 |
| 编辑把“计划今晚服药”误作已经服药，还会误算半枚余量 | 保留原评分与证据，允许作者写明原因后确认；摘要可人工改正 | 第5、7章定稿备注，不伪装成自动通过 |
| 自动修订后仍可能有时间矛盾 | 三轮后保留稿件，作者直接编辑，再核对 | 第5章“明日/后日”的实修 |
| 资金代价写得含糊 | 在正文写清让价三成后的七成现付、挪用哪笔钱 | 第6章人工编辑及复审 |
| 看似小的物品动作会多分一次红灰 | 作者核对整罐来源、一次分割、两方归属 | 第7章整罐当面等分，后文状态有来源 |
| 摘要可能把午前写成天亮前，影响后续上下文 | 摘要纳入审阅，和目前剧情、检索摘要一起保存 | 界面实修与事务测试 |
| 拒绝下一章记忆却仍更新结构化计划 | 下一章计划变更受接受选项控制 | 拒绝提案的回归测试 |
| 自动整理会改掉作者已确定的下一章目标 | 保留作者标题、目标和字数；只细化衔接 | 作者目标保留测试 |
| 事务成功、索引失败后恢复可能重复建版 | 同事务保存提交标记，恢复只重建索引 | 注入索引失败后恢复，版本仍只有一个 |
| 历史重写后，未改文字的后文也要能重新确认 | 允许待复核正文按新上下文建立新版本 | 两章真实作品与回归测试 |
| 导入稿缺早期快照，可能卡在第一章复核 | 保存导入原稿版本和初始参考记忆；保留标题与规划 | 导入—重审—再次定稿测试 |
| 预设章节写满后还需要同卷续写 | 工作台与规划页提供新增章节，按卷连续编号 | 基础版本与分卷隔离测试 |
| 编辑把角色有意违规也当成不能定稿的剧情矛盾 | 允许说明创作取舍，保留低分与问题；后文必须兑现后果 | 第10章提前借铃，公堂追责列入后续验收，原审阅保留 |
| 本机系统代理也接管localhost，验收客户端偶发连接超时 | 工作台的启动检测、终端和评估HTTP请求直连回环地址；官方模型请求保持原传输配置 | 配置不可达代理时，普通请求失败、直连仍成功；冻结后的传输修复及失败补跑另记 |
| 固定命名的设置临时文件可能跟随预先存在的链接，设置路径也可能在启动后改变 | 使用项目内独占创建的随机临时文件，每次读取和更新重验目录边界，保持0600权限 | 固定临时链接不会被写入；配置和环境文件越界链接回归 |
| 没有后续章节的末章重写，可能读到自己的已发生结果 | 所有已定稿章重写都回到前章快照，提交时先还原该快照，再应用所选变化 | 单章末稿重写、拒绝提案后不会留下旧后状态的回归 |
| 同名记忆提案出现两份，确认时可能互相覆盖 | 模型输出要求合并，同名所选提案在提交层拒绝；旧提案可逐项拒绝 | 第11章拒绝重复文档，模型与存储层回归 |
| 记忆提案重复生成程序负责的两份文档，且漏填reason，SDK还丢失解析错误 | 目前剧情与当前章节设计规划只由程序组装，模型对它们的写入被丢弃；其余唯一预期工具参数仍严格校验，缺项明确反馈；检查点只重试记忆步骤 | 第11章失败记录、原正文和审核保留，SDK降级解析回归 |
| 深度编辑在32000token上限仍可能被截断 | 该类重试降低思考强度，保留失败费用与实际配置；不伪造已完成审核 | 第10章真实截断日志，降级策略的离线回归 |
| 已失触的三指却重新有热感、听息后遗漏代价 | 通过正文编辑改用左掌根，补出咳血和失准；重新提取状态 | 第10章两轮界面修订与原稿对比 |
| 技能存在不等于执行记录能证明读过 | 记录实际工具调用；玄幻规划明确先读技能 | skill-harness-proof.json 中的 read_file 与 search_story |

程序能够验证来源文字存在、版本是否过期、同一资源状态来自哪一章，不能因此保证语义解释正确。第7章的半枚药判断是一个明确例子：同模型编辑仍会误报，作者的判断和原因必须保留下来。

“作者主导”在这里是一项实际的数据权限：作者能改正文、摘要和记忆，拒绝事实或下一章提案；这些选择会作用于正式存储和后续上下文。它也意味着样书成绩包含实施者的编辑劳动，不能宣传成完全自动创作的质量成绩。

原始证据位于 artifacts/evaluation/runs、ui-acceptance.json、restart-proof.json、planner-smoke.json、skill-harness-proof.json 与 artifacts/testing/pytest.xml。综合结论见最新实测报告。
