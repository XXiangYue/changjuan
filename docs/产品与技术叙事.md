# 长卷：把“下一章”变成能持续兑现的故事

## 产品主张

长卷为长篇作者提供一个能接续、可改稿、记得住前文的创作工作台。作者把握方向，Agent 负责找依据、写草稿、提出问题和整理状态；确认后，变化才成为故事的一部分。

一句介绍：**灵感由你掌舵，细节一起照顾。**

## 为什么长篇创作需要专门的 Agent 系统

长篇的难点不只是产出一段好看的文字。一本书同时维护人物欲望、视角知情、时间距离、资源消耗、能力边界和读者期待。它们随章节变化，且一处改动会影响后文。把所有资料塞进一次对话，也不能保证角色不会知道未来、用掉的药不会再出现、伏笔不会只铺不收。

科研 Agent 的完整工作链通常包含目标、证据、工具执行、检验与结果保存；创作也需要这些环节，但“好小说”没有单一正确答案。因此长卷把可确定的过程交给程序，把审美判断与剧情决定交还作者。

## 三个作者能感知的改变

**每次续写先建立“故事此刻”。** 全书方向告诉系统要去哪里；上章全文保证衔接；十份核心记忆、近十章摘要和时序状态说明已经发生什么；历史检索把相关原文带回来。人物的秘密、药的持有人、能力的代价不再只靠一段不断压缩的聊天记录。

**检查意见有位置，修订有上限。** 一致性和叙事编辑各自读稿，给出四维评分、原文引用、依据和改法。程序计算权重，最多返工三轮。作者可以采纳，也可以解释自己的创作选择，不必困在模型自我表扬或无限重写里。

**故事不会被一次错误提取悄悄改写。** 正文和记忆提案一起审阅，事实可逐条拒绝，核心文档可修改。数据库在一次事务中保存作者的决定，版本可回看，来源可跳转。中断恢复与预算限制使持续创作具备基本的工程可靠性。

## 技术亮点与实际入口

| 技术 | 解决的问题 | 作者在哪里用 | 对应证据 |
|---|---|---|---|
| 持久化 Agent harness | 多步骤任务易丢进度 | 写作中的暂停、恢复与运行记录 | LangGraph 检查点、重启测试 |
| 技能按需加载 | 一条通用提示难覆盖题材技巧 | 故事蓝图规划 | DeepAgents 只读玄幻技能、版本哈希与工具记录 |
| 时序状态与人物知情 | 未来泄漏、资源反复出现 | 故事资料库与编辑依据 | 来源章节、事实类型、位置过滤 |
| 中文混合检索 | 长篇信息相关但不在最近章节 | 资料搜索、右侧历史依据 | FTS5 + 本地 BGE + Qdrant、降级状态 |
| 按角色分配推理预算、独立编辑与有限反思 | 单次自评偏高、返工方向不清 | 审阅页、编辑引文与多轮草稿 | 两套消息上下文、最多三轮修订事件 |
| 提案与原子定稿 | 草稿猜测污染正式设定 | 正文与记忆联合确认 | 单事务、基础版本、正文哈希 |
| 可观察与费用治理 | 不知道为什么失败、花了多少 | 实验、设置、运行过程 | 真实 token、费用预留、保留失败 |
| 有来源的评估 | 技术叙事缺少验证 | 匿名阅读对比与实测报告 | 冻结案例、全量试次、两份完整稿 |

这些技术共同形成一个有限、可审阅的创作闭环。当前没有训练模型，没有强化学习，也没有把只读工具包装成“自主完成一切”。研究叙事应描述真实实现，不依赖没有落地的标签。

## 怎样讲清效果

演示时先展示作者的实际工作：决定章节冲突，生成一章，检查人物知情，拒绝一条提取错误，再定稿和接续下一章。随后打开资料库的原文来源、一次中断恢复记录和整卷导出。让可靠过程先于技术名词出现。

数据分为四类：程序规则检查、同模型判断、真实读者偏好、工程性能。最新数字以 artifacts/evaluation/实测报告.md 与 results.json 为准，不能把模型编辑分说成读者满意度，也不能把固定场景证据注入探针说成整套端到端系统消融。

另设真实执行图的续写压力验收：同样12个场景经过生产服务的检索、状态、生成、编辑、提案和版本提交，实际开关不同模块。四组共享基础规则，历史档案放在近十章之外，摘要故意遗漏该信息。这测的是指定缺口能否被补救，不是自然遗忘率；预置状态也不代表自动提取正确率。它复用了探针任务，不能把两个实验合并成192个独立样本。原文检索和结构化状态一起开关，目前不能拆开宣称某一种检索技术单独贡献多少。

对照采用相同初始设定、章节蓝图和模型。旧策略保留全量核心记忆与逐章生成、不自动返工的行为，运行在共用的新存储和模型适配层上。完整系统额外使用历史状态、混合检索和独立编辑。测试操作者为Codex AI助手，并非自然人作者；外部AI编辑不作为产品内角色或真实读者评价。样书第一章有实施者通过界面的审阅、事实拒绝与小范围改写；第5至10章也有期限、资源、知情来源和动作衔接的修订。第12章也补写了修炉材料、封条顺序与资源归属的兑现。逐章干预见 protocol-changes.json 与定稿备注，自动确认和界面确认均记入审计。这些区别必须与结果一起公开。

当前样本能说明系统是否完成一部玄幻短卷、机制在这些场景是否有帮助，不能证明“自动写出畅销小说”。下一步价值应由更多真实作者的持续使用、跨题材样本和更长期作品验证。

## 建议使用的公开表述

“长卷让创作 Agent 的每一章都有计划、有依据、可审阅、能恢复。它维护故事状态，并把正文和记忆的最终决定交给作者。我们用真实模型完成整卷创作，保留失败与费用，再用固定场景和匿名片段检查改进是否成立。”

避免宣称：零幻觉、绝不崩人设、自动保证原创、百万字无遗忘、全面超越旧系统。现有证据不足以支持这些话。
