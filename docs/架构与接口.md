# 长卷的架构与接口

## 边界与技术选择

长卷是单人本地应用。React、TypeScript、Vite、Tailwind 和 Tiptap 组成中文编辑前端；Python 3.12、FastAPI、Pydantic、LangGraph、DeepAgents 与 SQLite 组成应用服务。模型固定调用 DeepSeek 官方接口。依赖版本以 pyproject.toml、uv.lock、web/package.json 与 pnpm-lock.yaml 为准。

LangGraph 负责有限状态工作流、检查点和作者中断。DeepAgents 用于蓝图规划：按需读取玄幻创作技能、管理规划步骤、调用当前作品的只读检索工具、提交受 schema 约束的计划。规划员没有正式稿写权限，也没有任意终端能力。正文作者使用快速流式生成，两个编辑优先使用 high 档思考模式并以 JSON schema 校验结果；触及输出上限的重试降低到 low，降级事件和实际配置都有记录。先做确定性篇幅检查，再支出深度编辑预算；思考过程本身不落盘。正文作者和两个编辑采用独立消息上下文，不共享隐含对话历史；这是一种有边界的角色分工，不是无限自主的群体。

## 一章怎样成为正式故事

~~~mermaid
flowchart LR
  P[作者确认的章节目标] --> C[构造时序上下文包]
  C --> W[异步流式作者]
  W --> R[独立一致性编辑与叙事编辑]
  R --> D{评分与篇幅}
  D -->|最多三轮修订| W
  D --> M[事实与记忆提案]
  M --> H[检查点：等待作者]
  H --> T[数据库原子提交]
  T --> V[索引与 Markdown 镜像]
  V --> N[下一章规划]
~~~

作者的实际决定包含正文基础版本、作品记忆版本、接受的文档名称、文档全文覆盖值、接受的事实编号和备注。缺少完整审核、正文哈希变化、版本过期或事实引文不存在时不能提交。失败审核需要作者明确填写继续原因。

正文、记忆、事实、摘要、版本快照和提交标记使用同一 SQLite BEGIN IMMEDIATE 事务。全文检索和 Markdown 在事务后重建。模型不能直接定稿；HTTP 连接也不持有任务的生命周期。

任务恢复依赖 LangGraph SQLite 检查点。运行事件持久化、SSE 只负责传输。一个作品的活跃运行由数据库唯一索引限制。服务持有数据目录进程锁，防止误开第二个实例重置任务状态。run_commits 标记解决“事务已成功、检查点或索引尚未完成”时的重复执行。

## 记忆的四层

| 层 | 内容 | 作用 |
|---|---|---|
| 作者方向 | 全书方向、分卷与章节场景 | 定义要写什么；不等于已经发生 |
| 核心记忆 | 十份完整可读的中文文档 | 保留规则、状态、剧情和伏笔 |
| 时序状态 | 主体、谓词、值、类型、状态、来源版本、章节位置 | 查明在某一章之前成立的事实 |
| 历史证据 | 上章全文、近十章摘要、检索片段与引文 | 为续写和编辑提供可回看的依据 |

时序位置按卷号、章号编码；查询严格早于待写章节。结构化状态按主体和谓词取最近有效值；全部历史仍可从版本快照及正文查阅。人物知情与物品状态采用不同类型，不把作者知道的秘密自动算作角色知情。

历史章节重写使用之前的记忆快照，最后一章也一样；不会把本章旧版本已经发生的结果当成起点。提交时先回到该快照，再应用作者接受的变更。定稿时将该位置及之后的旧状态、旧片段失效，后续正式章统一标记待复核。保守失效比自动猜测语义影响更可靠，但会让作者复核一些实际无关的章节。

## 混合检索

正文按约 450 字符分块，重叠 70 字符。Jieba 加中文二元词处理自造人名和术语，SQLite FTS5 BM25 负责关键词召回。FastEmbed 的 BAAI/bge-small-zh-v1.5 生成本地 512 维向量，Qdrant 本地存储负责语义召回，再用 RRF 融合。

所有结果经过作品、章节位置、来源版本与失效标记过滤；未确认草稿不进入检索。重建章节索引会替换该章旧向量。向量不可用时显示降级状态，关键词与结构化查询继续工作。

这是时序故事状态与混合检索的组合；目前不实现图遍历推理或完整 GraphRAG。也没有训练模型、强化学习或跨作品共享私人记忆。

## 模型协议与费用

自由正文使用原生异步流式接口，token 增量小批量写入事件；结构化角色使用工具调用与 Pydantic schema。所有字段、评分范围和引文都需验证。目前剧情与当前章节设计规划由程序根据摘要及计划重建，模型不重复生成这两份派生文档。供应商适配层未给解析错误时，仅严格解析唯一且名称匹配的原始工具参数，不补造缺失字段。审核与事实提取可以引用段落编号，由程序直接取得正文原文，避免模型凭记忆抄错引文。限次重试记录原错误，长输出被截断时保留片段并停止冒充完整正文。

调用前在数据库事务中预留费用；调用后按返回 token 数结算估算值。并发请求共享预算。输入以 UTF-8 字节作保守预留上界，价格基准记录于每笔 usage。未知计费用量保守计入，不擅自释放。当前设置预算最多 300 元。

记录调用日期、返回的模型标识、角色、token、时长、输出结束原因、可获得的请求 ID、失败和重试。模型仅返回别名时，不能由此证明供应商内部的精确版本。2026-10-18核对的[官方更新](https://api-docs.deepseek.com/zh-cn/news/news261017/)称该别名已升级至V4.1-Flash-1017；实验仍只报告响应中实际出现的标识，不把路由说明当作独立的快照认证。规划 harness 记录版本、创作技能哈希和工具动作，不保存模型私有思维链。

## 主要 HTTP 接口

完整交互文档在服务的 /docs。URL 中的 ID 由服务生成，不能用任意文件路径替代。

| 接口 | 作用 |
|---|---|
| GET/POST /api/projects | 作品列表、创建 |
| POST /api/projects/{id}/chapters | 在指定卷追加章节，带作品基础版本 |
| GET /api/projects/{id} | 作品、目录、记忆、状态与运行 |
| PUT /api/projects/{id}/direction | 修改故事方向与文风，返回需核对的章节和记忆 |
| PUT /api/projects/{id}/outline | 带作品版本修改方向 |
| PUT /api/chapters/{id}/plan | 带基础版本修改章节计划 |
| PUT /api/chapters/{id}/draft | 乐观锁保存草稿、作废旧审核 |
| GET /api/chapters/{id}/versions | 正式版本历史 |
| POST /api/chapters/{id}/restore | 恢复为草稿 |
| POST /api/runs | 蓝图、新卷、写章、改写、重审 |
| POST /api/runs/{id}/approve | 提交作者的正文与记忆决定 |
| POST /api/runs/{id}/pause,resume,cancel | 任务控制，各为单独路径 |
| POST /api/runs/{id}/recover-draft | 从失败运行恢复作者输出 |
| GET /api/runs/{id}/events | SSE；after 或 Last-Event-ID 续接 |
| GET /api/runs/{id}/events?once=true | 有序事件 JSON 快照 |
| GET /api/projects/{id}/search | 有效正式稿证据查询 |
| POST /api/projects/{id}/reindex | 重建索引 |
| GET /api/projects/{id}/export | md、txt、zip 浏览器下载 |
| POST /api/projects/{id}/exports | 保存到工作目录并返回路径，校验符号链接边界 |
| POST /api/projects/import | 有大小和路径限制的 ZIP 导入 |
| GET/PUT /api/settings | 脱敏设置、保存密钥 |
| POST /api/settings/connect | 验证官方连接与模型可用性 |
| GET /api/research | 实验与匿名片段 |
| POST /api/blind/{id}/vote | 真实用户阅读选择 |

所有数据路径限制在项目根目录，解析绝对路径和符号链接后再做边界检查。私有设置每次读取/更新重验路径，保存使用本项目内独占创建的随机临时文件，保持0600权限。启动检测、终端与验收客户端的回环HTTP直连，官方模型传输配置独立。ZIP 只读取白名单结构，不直接解压。浏览器外域写请求与非回环 Host 被拒绝。此设计面向可信的本机用户，不应直接暴露到公网。

## 已知边界

机器引文校验只检查字面存在；事实的语义支持仍可能提取错误。编辑也会误报、漏报，评分不是文学质量证明。故事状态谓词尚未完全规范化，相同语义不同措辞可能并存。大纲变更不会自动保证全书所有因果都被改好。百万字规模、Windows 与多用户访问尚未做生产验收。
