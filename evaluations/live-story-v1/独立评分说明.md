# 《焰井还铃》独立AI阅读与证据校验

本轮只验证这份预先明确的三章故事承诺能否走完实际产品流程。新brief更明确，不将它与旧卷的差异纯归因于状态、检索或编辑。若基线和完整系统均兑现，照实报告共同成功。

规则已在生成前冻结。brief SHA256为 `44958dc8c2b1b33972dc88682b9fe764fc30c3bc264bdbd58fd51d0dbaa1e56d`；protocol SHA256为 `4c6e29bce61fb0e3fa32dc860e7a8fb74837d8a21148ca45407a83840885242a`。评分脚本同时核验两项指纹，不会改写输入或调用模型。

## 匿名文本包

操作者在实际UI完成两轨迹，保存正式正文、计划、审阅、提案、接受/拒绝、版本和导出。实际工作流配置与版本映射另存，不交评审者。匿名包只含以下字段，正文不带章节标题，字节和换行不再清洗。

```json
{
  "entry_id": "A",
  "chapters": [
    {"number": 1, "title": "章题", "body": "第1章完整正文", "sha256": "正文UTF-8字节SHA256"},
    {"number": 2, "title": "章题", "body": "第2章完整正文", "sha256": "正文UTF-8字节SHA256"},
    {"number": 3, "title": "章题", "body": "第3章完整正文", "sha256": "正文UTF-8字节SHA256"}
  ]
}
```

`sha256`可省略，由脚本重新计算。不得夹带项目名的full/baseline后缀、配置、编辑分、工具轨迹或费用。三个章号不能缺失；未完成的轨迹保存运行失败报告，不伪造空章凑完成数。

## 阅读与填写

评审者先读brief与protocol，再按匿名包逐章阅读。每章的六项约束只使用本章或更早的证据，全卷再判最终六约束及三项兑现。区分实际动作、人物自述与书面记录。先前章节尚未到还钳时限，不因尚未回收就判违规；缺失步骤用 `not_tested` 或 `satisfied:false`，不编造不存在的反面原句。

可以生成待填模板：

```bash
.venv/bin/python /Users/lsf/Desktop/小说创作agent系统/scripts/score_live_story.py \
  --packet /Users/lsf/Desktop/小说创作agent系统/artifacts/evaluation/live-story-v1/packet-A.json \
  --template
```

模板含 `chapter_assessments`、`whole_constraints`、`payoffs`、`narrative`、`overall_comment`和`limitations`。每项填写具体理由。`preserved`、`violation`、成立的兑现步骤及所有叙事评分需要证据：

```json
{
  "chapter": 2,
  "quote": "对应匿名正文中的连续原文，不得改字或拼接",
  "source_kind": "narrated_action"
}
```

`source_kind`只能是 `narrated_action`、`character_statement` 或 `written_record`，引文长度6–220字符。短确认语可以连同实际接收动作一起引用；不能把“准备还”“以后会停”标成已经归还或已经停止。没有某步骤时说明缺口即可，不强求给“缺失”找引文。

兑现规则为P1八步、P2五步、P3六步。所有必需步都满足才记3分完整，只有铺垫记1，存在推进但缺环记2，全无记0，总分最高9。重现铃声、领药者自认、接钳确认及归钳后的真实工具损失均是独立必需条件，不能靠较好文笔抵消。

四项叙事评分依protocol的0–4锚点，分别说明人物选择与代价、因果理解、场景节奏、人物声音。它们是AI阅读判断，不是真人偏好票。程序通过仅表示它对这些AI标签正确计算了固定门槛，不证明AI语义判断正确。

## 校验、封存与解盲

先保存原始assessment，再运行以下校验。脚本要求绝对路径且都在工作目录内；已有不同内容的结果不会被覆盖。

```bash
.venv/bin/python /Users/lsf/Desktop/小说创作agent系统/scripts/score_live_story.py \
  --packet /Users/lsf/Desktop/小说创作agent系统/artifacts/evaluation/live-story-v1/packet-A.json \
  --assessment /Users/lsf/Desktop/小说创作agent系统/artifacts/evaluation/live-story-v1/assessment-A.json \
  --output /Users/lsf/Desktop/小说创作agent系统/artifacts/evaluation/live-story-v1/result-A.json
```

结果保存正文、匿名包、原始评审、规则和校验脚本的SHA。两轨迹结果都保存及封存后再揭晓配置。引文不合法时修正的是抄引或数据结构，保留旧评审版本及修正原因；不能因偏好或分数不好重新读稿挑结果。运行失败、长度未达、兑现缺环和无优势结论同样保存。

自检入口：`scripts/score_live_story.py --self-test`。这只检验引文字面、章节边界、必需证据与评分运算，离线夹具不计入创作或模型效果。

最终比较只报告这两条三章轨迹。六章不是六本独立小说，也没有自然人作者满意度或读者追读率。评审者参与了协议设计且为AI，应与一般文学质量结论保持区分。
